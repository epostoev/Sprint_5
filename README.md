# Sprint_5


## Список реализованных тестов

### 🛒 Работа с объявлениями (`TestAdvertisement`)
Класс тестов, проверяющий логику создания и отображения пользовательских объявлений.

| Тест | Описание |
|:---|:---|
| `test_created_unauth` | **Проверка прав доступа:** Проверяет, что неавторизованный пользователь не может создать объявление. Ожидается появление всплывающего окна (popup) с требованием авторизации. |
| `test_created_ad_auth_user` | **End-to-End сценарий:** Проверка полного цикла создания объявления. Включает заполнение всех полей формы, выбор города и категории, публикацию и автоматический поиск созданного товара на последней странице профиля. |

### 👤 Авторизация и регистрация (`TestRegistration`)
Класс тестов для проверки управления доступом и валидации полей ввода.

| Тест | Описание |
|:---|:---|
| `test_registrion_successful` | **Позитивный сценарий:** Регистрация нового аккаунта с динамически генерируемым email. Проверяется переход в состояние "Авторизован" (появление аватара и имени пользователя). |
| `test_registration_invalid_email_format` | **Негативный сценарий:** Проверка валидации email. Тест подтверждает появление текста «Ошибка» и смену цвета границ полей (border-color) на красный при вводе некорректного адреса. |
| `test_registration_already_exists_user` | **Негативный сценарий:** Проверка защиты от дубликатов. Пользователь не может зарегистрироваться на почту, которая уже есть в системе. |
| `test_login_user` | **Позитивный сценарий:** Вход под существующей учетной записью. Проверяется корректность отображения данных профиля после авторизации. |
| `test_logout_user` | **Позитивный сценарий:** Проверка функции выхода. Убеждаемся, что сессия завершается, данные пользователя скрываются, а кнопка входа возвращается в исходное состояние. |

## 🛠 Технические особенности реализации

* **Page Object Model (Локаторы):** Все селекторы вынесены в отдельный файл `locators.py` для удобства поддержки кода.
* **Динамические ожидания:** Вместо нестабильных пауз `time.sleep`, в проекте используются `Explicit Waits` (явные ожидания):
    * `EC.staleness_of`: используется для определения момента смены страницы при пагинации (когда старый элемент исчезает из DOM).
    * `EC.invisibility_of_element`: для подтверждения успешного закрытия модальных окон после действий.
* **Валидация через CSS:** Для тестов регистрации реализована проверка цветовой индикации ошибок через метод `value_of_css_property('border-color')`.
* **Уникальность данных:** Использование модуля `datetime` в названиях объявлений и генератора случайных email позволяет запускать тесты многократно без конфликтов данных в базе.
